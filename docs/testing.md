# 검증 설계와 성공 기준

검증은 네 층으로 구성한다. 외부 서비스의 가용성과 로컬 코드의 정확성을 같은 성공 표시로 합치지 않는다.

## 기본 검증: 네이버 요청 없음

| 단계 | 통과 기준 |
|---|---|
| 정적 검사 | Ruff의 E4·E7·E9·F 오류 없음 |
| 공개 파일 검사 | Git 공개 대상 소스·문서에 개인 절대 경로·JWT 원문·실제 매물번호가 들어간 응답 자료 없음 |
| 회귀 검증 | 단위·계약·MCP 테스트 전체 통과, articles.py와 studio.py 분기 포함 커버리지 85% 이상 |
| stdio 발견 | 기존 도구를 포함한 11개 도구명과 입력 스키마 확인 |
| stdio 저장본 검토 | 익명화한 광고를 실제 MCP 연결로 분류. 인터넷 요청 없음 |

공개 파일 검사는 제한된 패턴 검사이며 완전한 비밀정보 검사기는 아니다. PR 작성자는 원문 자료·연락처·쿠키 등도 별도로 확인해야 한다.

계약 자료는 실제 목록·상세의 필드 구조를 유지하되 매물번호를 900000 계열 가상 값으로 바꾸고 주소·연락처·사진 경로를 제거했다. 테스트의 기대값은 서버 구현으로 자동 생성하지 않는다.

중요한 실패 사례는 월세 150만원 경계, 보증금과 월세 혼동, 공급면적 대용, 목록의 정수 면적과 상세 소수점 차이, 지하 층수의 부호, 저·중·고층 미확인, 사진 목록 누락과 실제 빈 목록, 상세 매물번호 누락·불일치, 응답 형식 변경, 200 안의 오류, CAPTCHA·401·403·429와 후속 호출 중단이다. 아파트의 불필요한 추가 페이지 수집도 회귀 검증한다.

## 명시적 실시간 검증

`python scripts/verify.py --live`는 기본 검증을 먼저 통과한 뒤 실제 stdio 서버에서 다음을 확인한다.

1. 상가·사무실 목록에 실제 광고가 있고, 반환된 적합 광고가 유형·월세·층수·필수 정보 조건을 만족한다.
2. 개별 상세의 매물번호가 요청한 번호와 일치하고 전용면적·월세를 읽을 수 있다.
3. 공개 사진 URL이 적어도 하나 있으며 HTTPS URL 계약을 만족한다. 사진 없는 샘플은 `--photo-article`로 명시한 다른 공개 광고로 확인한다.
4. 기존 아파트 월세 검색에서 실제 광고·월세를 반환한다.
5. 아파트 상세의 사진 상태도 유효하다. 공개 사진이 없으면 정확히 `not_published`와 빈 목록이어야 한다.

마지막 항목은 아파트 사진이 반드시 등록돼 있다는 기준이 아니다. 아파트 사진이 실제로 있다는 주장은 `available`과 URL 수가 확인된 경우에만 한다.

검증은 성공 기준을 낮추며 반복하지 않는다. 코드·응답 매핑 오류를 고치고 다시 실행하며, 접근 제한은 `blocked`로 남겨 추가 네이버 요청을 중단한다. 소량의 제한된 조회가 성공했다고 전체 동·모든 광고·영구 가용성을 보장하지 않는다. 광고를 새 후보로 등록하거나 기존 후보 확인일을 자동 갱신하지 않는다.

## 결과와 재현

결과 JSON에 실행 시각(UTC), 소스 해시, 각 검증 상태와 수집·사진 수를 남긴다. 매물번호·광고 원문·사진 URL·토큰·쿠키는 남기지 않는다. 소스 해시는 루트·scripts·tests의 Python 소스, 계약 JSON, 의존성 명세를 포함한다.

- `passed` / 종료 코드 0: 선택한 검증 단계 모두 통과. `mode=offline`은 실시간 성공이 아니다.
- `failed` / 종료 코드 1: 코드·계약·조건·표본에 따른 실패. 누락 단계를 통과로 표시하지 않는다.
- `blocked` / 종료 코드 2: 접근 제한. `liveVerified=false`이며 제한 이후 추가 요청 없음.

실행 결과는 `.verification/latest.json` 등 현재 파일만 유지하고 Git에서 제외한다. GitHub Actions는 Python 3.10·3.12·3.13의 기본 검증만 실행하며 네이버에 요청하지 않는다. 원격 CI 결과는 실제 실행된 후 확인한다.
